**LinkedIn** (under 1200 characters)

If you ever pushed a key to GitHub by mistake and deleted it a minute later, assume it is already copied.

A dev.to roundup (Nov 8) reports that Microsoft Threat Intelligence, on Nov 5, described attackers using AI agent tooling to find secrets left in public GitHub repos. In one case it says an agent went from an exposed secret to reading a cloud key vault in about five minutes. I only read the roundup, not Microsoft's post, so check the source.

You do not need an AI tool to fix this. Four habits for any web developer:

1. Keep keys in environment variables, never in code or in .env files you commit.
2. Add a secret scanner as a pre-commit check.
3. If a key leaks, rotate it first. Deleting the commit is not enough.
4. Give every key the smallest access it needs.

This matters more when you build AI apps, because model keys cost real money.
