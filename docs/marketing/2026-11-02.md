## a. Today's angle
Model output is untrusted input: if your app runs code an AI wrote, put it in a real sandbox. AI Weekly (Nov 1) reports that JFrog disclosed CVE-2026-120338, a CVSS 10.0 flaw in Prefab UI's generative UI sandbox (versions 0.14.0 to 0.20.2). It says LLM-written Python ran inside Pyodide in a Deno subprocess with excessive permissions, allowing file read/write and code execution as the server user, and that 0.21.0 fixes it. Why it matters to web developers: "let the model write code and run it" is an easy feature to add and an easy one to get wrong. Earlier packs covered approvals, keys, logs and evals; this one is about where generated code runs.

Source: [AI Weekly, AI News Today, November 1](https://aiweekly.co/ai-news-today). Primary advisory not opened.

Who runs the code your AI writes?

AI Weekly (Nov 1) reports that JFrog disclosed a CVSS 10.0 flaw in Prefab UI, a tool that runs Python written by an LLM. For web developers adding AI features, the lesson is simple: model output is untrusted input. Treat generated code like code from a stranger.

What I would check this week:
1. Run generated code in a sandbox with no file access and no network by default.
2. Set a time limit and a memory limit.
3. Give it only the permissions it needs, then remove half.
4. Never run it as the same user that owns your app.
5. Log every run, and test the sandbox with code that tries to escape.
