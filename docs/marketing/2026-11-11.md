A Dev.to news digest (Nov 11) says Google engineers describe "agent distraction": stale TODOs, dead code and old patterns send coding agents in the wrong direction. I saw the summary, not the original article, so check the source before you quote it.

It makes sense to me. An agent reads your files the way a new teammate does. If three old ways of fetching data sit side by side, it may copy the wrong one.

A 30 minute cleanup for any web project:

1. Delete dead files and unused functions.
2. Remove TODOs that are no longer true, or turn them into real tasks.
3. Pick one way to do each common job (fetching, errors, forms) and remove the old ones.
4. Add a short rules file: how to run tests, where things live, what not to touch.
5. Run your tests after every agent change.

Boring habits, big effect.
