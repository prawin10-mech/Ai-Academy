## a. Today's angle
Cursor released an Agent SDK on Oct 26 (CellCog, Startup Fortune): an agent is a folder in your repo, with the prompt in a Markdown file and each tool as a TypeScript file, plus built-in tests that check which tools the agent called. For web developers this is good news: agents are now normal code you review in a pull request, version in Git and test in CI. The skill that matters is writing the tests. Earlier packs covered approvals, logs, sandboxes and caps. Today is about treating the agent like any other code in your repo.

Sources: [CellCog, Cursor Agent SDK](https://cellcog.ai/blog/cursor-agent-sdk/), [Startup Fortune, Oct 27](https://startupfortune.com/cursor-turns-its-coding-agent-into-a-typescript-sdk-anyone-can-build-on/)

**LinkedIn** (about 1000 characters)

Your next AI agent might just be a folder in your repo.

Cursor released an Agent SDK on Oct 26 (per CellCog and Startup Fortune). The idea: the prompt lives in a Markdown file, each tool is a TypeScript file, and you can run built-in tests that check which tools the agent called.

I like this because web developers already know this workflow. Pull request, code review, Git history, CI. The agent stops being magic and becomes code.

If you build agents this way, keep these habits:
1. Review prompt changes like code changes. They change behaviour too.
2. Keep each tool small, with typed inputs you validate.
3. Save 15 to 20 real tasks with the tool calls you expect, and rerun them after every change.
4. Keep a rollback ready.

I am not saying use Cursor. The habit works with any framework.
