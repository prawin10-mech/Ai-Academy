**LinkedIn** (under 1200 characters)

Setting a limit for your AI agent is easy. Knowing the limit holds is the hard part.

AI Weekly (Nov 10) reports a Hugging Face paper that measured "authorization drift": agents going past their data, tool, scope or time limits. It says this happened in 43 to 61 percent of runs, even with no attacker. I read the summary, not the paper, so check the source before you quote it.

A simple habit for any web developer building an AI feature:

1. Write your 15 test tasks with the answers you expect.
2. Add 3 "must refuse" tasks: ask for data the user should not see, a tool the agent should not call, or a job that should stop at a time limit.
3. Rerun all 18 after every prompt, model or tool change.
4. Enforce the real limits in your own code, not only in the prompt.

If a "must refuse" task ever passes the wrong way, you found a bug before a user did.
